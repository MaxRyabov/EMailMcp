## Why

Нужно, чтобы Claude Code мог анализировать входящую почту, в первую очередь ящик в Яндекс Почте (личный или в организации Яндекс 360), без возможности что-либо в ящике изменить. Upstream `imap-mcp` уже ограничен чтением на уровне кода, но входит только по паролю. Пароль приложения даёт полный доступ к ящику, включая SMTP и удаление, поэтому «только чтение» держится лишь на честности кода. Яндекс выдаёт OAuth-право `mail:imap_ro` («Доступ на чтение писем в почтовом ящике»). С ним ограничение обеспечивает сам провайдер, а код становится вторым слоем защиты.

Второй повод: upstream не годится для анализа писем на русском и с вложениями. Поиск идёт в US-ASCII, вложения не видны, тело письма приходит без ограничения размера, список писем скачивается целиком. А параметры инструментов, которые заполняет модель, уходят в IMAP без проверки.

## What Changes

- **Способ входа задаётся для каждого аккаунта.** В `accounts.toml` появляется поле `auth`: `password` (по умолчанию, совместимо с upstream) или `oauth` с полем `oauth_provider`. Первый провайдер — `yandex`. Протокольные особенности провайдера (имена параметров, grant type, коды ошибок, срок предупреждения об истечении) описываются данными профиля.
- **OAuth Яндекса через device flow.** Команда `imap-mcp auth <account>`:
  - запрашивает строго `scope=mail:imap_ro`, передаёт стабильный `device_id`;
  - сразу после получения токена проверяет вход в IMAP;
  - хранит токены в Windows Credential Manager через `keyring` (локально, без перемещения с профилем).

  Вход в IMAP идёт через `AUTHENTICATE XOAUTH2`. Дополнительные команды:
  - `auth --trace` — показ обмена HTTP и IMAP с вырезанными секретами;
  - `status [--offline]` — статусы аккаунтов с реальным входом или без сети;
  - `forget <account>` — отзыв токена у провайдера (при наличии `client_secret`) и удаление из хранилища.
- **Повторная авторизация вручную раз в год.** Автообновления токенов нет. За 30 дней до истечения `status` и `list_accounts` предупреждают, после истечения — статус `reauth-required` с командой. Отказ входа при действующем токене тоже даёт `reauth-required`, и подсказка перечисляет обе причины: «доступ отозван» и «IMAP с OAuth выключен или запрещён администратором».
- **Гарантия «только чтение» для всех аккаунтов, включая парольные:**
  - папки открываются только через `EXAMINE`;
  - IMAP-клиент пропускает только команды из allowlist;
  - в аргументах команд запрещены CR, LF и NUL (закрывает внедрение команд через параметры инструментов);
  - в `FETCH` разрешены только элементы, не меняющие флаги;
  - после любого нарушения соединение закрывается.
- **Проверка на живом сервере:** команда `imap-mcp verify-readonly <account>` выполняет безопасные пробы с гарантированным откатом и отличает «провайдер запретил» от «проверка неполная».
- **Проверка аргументов инструментов:** формат идентификаторов, границы чисел, длина строк.
- **Непрозрачные идентификаторы писем:** в id закодированы аккаунт, папка, UIDVALIDITY и UID. Письмо из другой папки или другого ящика нельзя получить по ошибке, устаревший список распознаётся. Так же будущий бэкенд (например, Gmail API) сможет выдавать свои id без изменения инструментов.
- **Папки:**
  - инструмент `list_folders`;
  - параметр `folder` в `list_emails` и `search_emails`;
  - псевдонимы special-use (`\Junk`, `\Sent`, …), которые разрешаются для каждого аккаунта отдельно.
- **Письма на русском:** поиск по кириллице — три запроса `UID SEARCH CHARSET UTF-8` с литералом, результаты объединяются.
- **Ограничения объёма:**
  - верхняя граница `limit`;
  - список строится в два прохода с бюджетом байт, а ответ ограничен 45 000 символов;
  - HTML переводится в текст, скрытый текст удаляется;
  - тело читается постранично (`offset`, `next_offset`), потолок 40 000 символов.
- **Вложения:**
  - метаданные в `get_email`;
  - инструмент `get_attachment_text` для PDF, DOCX и TXT;
  - тип определяется по сигнатуре;
  - разбор в отдельном процессе с таймаутом, лимитом памяти и принудительным завершением;
  - лимиты размера и страниц;
  - кэш последних писем, чтобы не скачивать письмо заново ради каждого вложения.
- **Надёжность:**
  - тайм-аут сокета и дедлайн на аккаунт в рамках вызова;
  - переиспользование соединения с аккаунтом;
  - ошибка в описании одного аккаунта не выводит из строя остальные;
  - правка `accounts.toml` подхватывается без перезапуска.
- **Секреты не утекают в выдачу:** каждый инструмент обёрнут так, что любой текст ошибки проходит редактирование токенов, паролей и `client_secret`.
- **Рабочее место для Claude Code:**
  - шаблон папки с `.mcp.json` и `.claude/settings.json`;
  - режим `dontAsk`: разрешены только инструменты `imap-mcp`, всё остальное отклоняется автоматически;
  - отключены коннекторы claude.ai и посторонние MCP-серверы;
  - второй слой запретов: сеть, shell, запись файлов.

  Плюс инструкция на русском для личного ящика и для Яндекс 360.
- **BREAKING (относительно upstream, внешних потребителей у форка нет):**
  - `id` писем становится непрозрачной строкой;
  - `get_email(id)` больше не принимает `account`: аккаунт и папка содержатся в id;
  - `list_emails`, `search_emails` и `list_accounts` возвращают объект (`rows` / `accounts`, `errors`, признаки урезания) вместо списка;
  - в строках списка `snippet` может быть `null`, добавлены `size` и `folder`.

## Capabilities

### New Capabilities

- `account-auth`: аккаунты и способы входа (пароль, OAuth); получение, хранение, контроль срока, отзыв и удаление OAuth-токенов; статусы аккаунтов; изоляция ошибок конфигурации; защита секретов в выдаче.
- `readonly-imap-access`: гарантии отсутствия изменений в ящике: `EXAMINE`, `BODY.PEEK`, allowlist команд и элементов `FETCH`, запрет CR/LF в аргументах, fail-closed; проверка на живом сервере.
- `mail-tools`: MCP-инструменты для списка, поиска и чтения писем и папок; проверка аргументов; формат id; ограничения и постраничность выдачи; тайм-ауты и переиспользование соединений.
- `attachment-text`: метаданные вложений и извлечение текста из PDF, DOCX и TXT с изоляцией и ограничениями.

### Modified Capabilities

Нет. Канонических спек в `openspec/specs/` пока нет. Сохраняемое поведение upstream зафиксировано в новых спеках как ADDED.

## Impact

- **Код:**
  - `src/imap_mcp/accounts.py` — новые поля, валидация по аккаунту, перечитывание по mtime;
  - `src/imap_mcp/imap.py` — провайдер учётных данных, EXAMINE, два прохода, HTML→текст, пул соединений;
  - `src/imap_mcp/server.py` — новые инструменты и параметры, `@safe_tool`, проверка аргументов.
  - Новые модули: `auth/` (пароль, OAuth, профили, хранилище), `guard.py`, `ids.py`, `htmltext.py`, `attachments.py`, `cli.py` (`serve`, `auth`, `status`, `forget`, `verify-readonly`).
- **Точка входа:** `imap-mcp` без аргументов по-прежнему запускает MCP-сервер на stdio.
- **Зависимости:**
  - `keyring` (хранилище токенов);
  - `pypdf` и `cryptography` (PDF, включая AES);
  - `defusedxml` (DOCX без `lxml`).

  HTTP — через `urllib.request` из стандартной библиотеки, без новой HTTP-библиотеки.
- **Окружение:**
  - нужен `uv` (не установлен), Python 3.12 через `uv`;
  - регистрация приложения на oauth.yandex.ru с единственным правом «Доступ на чтение писем в почтовом ящике»;
  - включённый IMAP с OAuth-токенами в настройках почты;
  - для Яндекс 360 — разрешение администратора организации на IMAP и сторонние OAuth-приложения.

  Сеть: прямой выход на `imap.yandex.com:993` и `oauth.yandex.ru:443` (подтверждено пользователем).
- **CI:** матрица дополняется `windows-latest` и Python 3.14.
- **Тесты:** набор upstream адаптируется. Новые тесты без сети: фейковый сокет для охранника, фейковый HTTP opener, keyring в памяти, фикстуры вложений. Живые проверки выполняет пользователь (`auth`, `verify-readonly`, сессия Claude Code).
- **Лицензия:** сохраняется MIT и копирайт upstream, добавляется строка о форке.
- **Будущие провайдеры:** OAuth для Gmail через IMAP не даёт права только на чтение. Read-only Gmail потребует отдельного бэкенда на Gmail API (`gmail.readonly`) — это отдельное изменение. Инструменты и формат id к этому готовы, сам бэкенд в изменение не входит.
