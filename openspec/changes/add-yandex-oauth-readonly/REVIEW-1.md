## Что пропущено

29. Сбой сети при refresh, когда токен ещё действителен: продолжать со старым токеном, а не ставить `reauth-required`.
30. Refresh прошёл, а запись в keyring упала: пара токенов может потеряться; порядок шагов не описан.
31. Ошибки Яндекса `unauthorized_client`, `invalid_scope`, `bad_verification_code`; Ctrl+C при опросе; нет сети при `auth`.
32. Нет `imap-mcp forget`: удаления токенов и отзыва доступа.
33. Одна ошибка в `accounts.toml` кладёт все аккаунты (`_load` с `lru_cache`, `_targets` вне try); правка конфига требует перезапуска.
34. Частота входов: новый TLS и AUTHENTICATE на каждый вызов, возможные лимиты Яндекса, нет переиспользования соединения и backoff.
35. Крайние случаи: папки `\Noselect` в `list_folders`, письмо без вложений, пустая папка, ни одного включённого аккаунта.
36. Корпоративная сеть: прокси для IMAP, закрытый порт 993, TLS-инспекция; текст ошибок не определён.

## Что сделано хорошо

- Эшелонированная защита: scope провайдера, EXAMINE, allowlist (не denylist) с проверкой подкоманды `UID`; `_command` в 3.12 действительно единственная точка отправки команд.
- Факты об upstream и imap-tools в Context верны.
- `scope` передаётся явно и не задаётся через toml.
- Старые токены сохраняются при неудачной повторной авторизации; токены читаются при каждом входе.
- У задач проверяемые критерии; базовая линия «31 тест» совпадает с кодом.
- Лимиты для вложений и чёткие Non-Goals.
